# 故障排查：wx-export

先看后端日志（容器方式运行）：

```bash
docker compose -f compose/docker-compose.dev.yaml logs --tail 100 backend
```

本地进程方式运行则看 `python main.py` 的控制台输出。

## 症状 → 处理

| 症状（脚本输出或现象） | 原因 | 处理 |
|---|---|---|
| `无法连接 http://127.0.0.1:8001 ...（服务未启动？...）` | 服务没起或端口不对 | 从源码构建和启动见 `docs/fork-docker-build.md`；用 `curl -fsS --max-time 10 http://127.0.0.1:8001/api/v1/wx/sys/base_info` 探测，不需要登录。服务在别的地址时给脚本传 `--base`。 |
| `登录失败` / `HTTP 401 .../auth/login` | 用户名密码与初始化时不一致 | 本项目没有注册，账号是 `init_sys.py` 从环境变量 `USERNAME`/`PASSWORD` 初始化的（默认 admin）。用 `.env` 里的真实值传 `--user/--password`，或设置 `WEMPRSS_USER/WEMPRSS_PASS`；仍不确定就直接问用户。 |
| `微信公众号授权已过期（无可用会话）...` | 服务报告当前无有效会话 | 让用户打开 http://127.0.0.1:5173 扫码重新授权，完成后再重跑。Dev Compose 默认尝试每 12 小时续期已有会话，但不能恢复已失效的会话。 |
| `抓取失败: ...`（任务 failed/error） | 文章被删/仅自己可见、链接不是文章页、微信风控或出口 IP 被限 | 先在浏览器/手机确认链接能打开，并确认是 `mp.weixin.qq.com` 文章页。IP 被限时用项目 compose 的 `singbox` 侧车 + `.env` 的 `PROXY_URL`，不要另配代理。再看后端日志确认具体错误。 |
| `等待文章抓取超时` / `等待导出任务超时` | 队列排队，或图片多、抓取慢 | 后端没卡死时增大 `--timeout`（默认 300 秒）重跑；确认后端 CPU/内存正常。 |
| `导出失败: ...` | 后端导出任务报错 | 看后端日志定位；修复后重跑（幂等，会原地覆盖）。 |
| `导出包解析失败（BadZipFile/...）` 或 `下载的导出包异常（过小）` | 下载中断或服务重启导致半截包 | 直接重跑一次；临时 zip 和半截解包目录已自动清理，不会留垃圾。 |
| `连接 ... 中断（...），服务可能正在重启` | 服务重启中 | 等几秒重跑。 |
| `verify_export` 报 `remote_images` 非空 | 部分图片下载失败，md 保留原 URL 兜底 | 重跑导出（图片会重新尝试本地化，幂等补齐）；反复失败时检查容器网络/代理。 |
| `verify_export` 报 `missing` 非空 | md 引用的图片文件丢失（被手工移动/删除） | 重跑导出修复；不要手工改 md。 |
| 目录名是 `local-<时间戳>` | URL 里没提取到 sn（不是标准文章链接） | 用文章页的原始 URL 重跑；`/s/<sn>`、`/s?__biz=...&sn=...` 两种形态都能识别。 |
| 出现 `index.corrupt-<时间戳>.json` | 索引曾损坏，已自动备份并从 `meta.json` 重建 | 无需处理；确认新导出的条目都在新索引里即可。 |

## 不要做的事

- 不要手工编辑 `index.json`/`meta.json`，也不要手工改 md 里的图片链接来"修复"导出——重跑脚本是幂等的自愈方式。
- 不要为导出临时修改服务端代码或绕过登录/授权检查。
- 不要把 `downloads/` 下的产物 commit 进仓库（`.gitignore` 已忽略）。
